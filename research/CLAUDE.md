# research/ — the research day

One file per question, ≤200 lines, Markdown. Every claim that a mechanic is fun or hated cites a source (a talk,
patch notes, a designer interview, a widely-cited community analysis, or a game's own documentation), with the URL.
Structure of every brief:

1. **The question** (one line).
2. **What the best games do** — 5–10 concrete mechanics, each: game, the mechanic in one sentence, why it works
   (the psychological or systemic reason), source.
3. **What players hate** — 3–6 items, same shape.
4. **Steal / adapt / avoid** — three lists for Keyrun, each item tied to the constraint set (≤5 rotational abilities,
   ≤10 keybinds, synergy-first, top-down 2D, no art).
5. **Verdict** — ≤120 words: the one design decision this brief recommends, stated so the bible can adopt it verbatim.

No fabricated sources. If a claim cannot be sourced, mark it `[unsourced opinion]` and keep it to one line.
